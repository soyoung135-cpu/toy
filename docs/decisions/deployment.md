# 배포와 접근 제한

## Decisions

- 앱은 Vercel 무료(Hobby) 요금제에 배포해 휴대폰 브라우저에서 `https` 주소로 연다.
- 배포된 앱은 Supabase Auth 계정 로그인으로 막는다. 로그인하지 않으면 대화 화면과 AI를 부르는 서버 기능을 쓸 수 없다.
- 로그인 방식은 이메일·비밀번호 하나다. 새 가입은 Supabase 설정에서 닫고, 내 계정만 대시보드에서 만든다. 앱에는 가입 화면이 없다.
- 운영 환경에서 Supabase 환경 값(`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`)이 없으면 모든 요청을 막는다. 열린 채로 배포되지 않게 하기 위해서다.
- LLM API 키는 서버에서만 쓰고 브라우저로 내려보내지 않는다. 브라우저에는 Supabase 공개용(publishable) 키만 내려가며, service_role 키는 쓰지 않는다.

## Boundaries

- 가입 화면, 이메일 확인, 비밀번호 재설정, 다른 로그인 방식(Google 등)은 이 결정에 포함되지 않는다. 필요해지면 다시 정한다.
- 로그인은 모르는 사람이 내 API 비용을 쓰지 못하게 막는 용도다. 그 이상의 보안 하드닝은 범위 밖이다.
- 배포 전 PC 개발 서버(`localhost`)에서 Supabase 환경 값을 설정하지 않고 쓰는 동안에는 로그인을 요구하지 않는다.

## Why

지하철에서 휴대폰으로 음성 대화를 하려면 브라우저가 마이크를 허용하는 `https` 주소가 필요하므로, PC 개발 서버만으로는 핵심 사용 장면을 만족할 수 없다. Vercel은 이 프로젝트의 Next.js를 그대로 올릴 수 있고 개인용은 무료다.

주소를 아는 누구나 앱을 열면 AI 호출 비용이 내 API 키로 청구되어 "비용 부담이 없어야 한다"는 제품 경계가 깨진다. 처음에는 비밀번호 하나로 막으려 했지만, 사용자가 대화 기록 저장 등을 위해 Supabase를 연결할 계획이어서 그 계정 로그인으로 접근도 함께 막기로 했다(사용자 확정). 가입이 열려 있으면 낯선 사람이 가입해 같은 문제가 생기므로 가입을 닫고 내 계정만 쓴다(사용자 확정).

## Reconsider when

- 다른 사람도 쓰게 되어 사용자별 데이터 구분이 필요해질 때
- Vercel 무료 요금제의 제한(함수 실행 시간, 사용량)에 걸려 대화가 끊길 때

## Still-rejected alternatives

- PC 개발 서버만 사용 — 휴대폰에서 마이크를 쓸 수 없어 지하철 사용이 불가능하다.
- 로그인 없이 공개 배포 — 주소가 새면 API 비용을 남이 쓸 수 있다.
- 접속 비밀번호 하나 — 구현은 가장 가볍지만, Supabase를 연결하면 계정 로그인과 이중 체계가 된다; Supabase 연결 계획이 취소되면 다시 본다.
- 가입을 열어 두고 가입자를 따로 거르기 — 가입 허용 목록 같은 추가 장치가 필요하고 개인용 앱에는 과하다; 여러 사람이 쓰게 되면 다시 본다.
