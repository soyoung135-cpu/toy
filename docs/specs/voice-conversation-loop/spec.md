# PC에서 페르소나와 영어 음성 대화를 하고, 끝나면 교정 보기

제품 맥락: [PRODUCT.md](../../../PRODUCT.md) — 이 작업은 핵심 흐름(새 대화 → 음성 대화 → 종료 → 교정)을 PC에서 처음으로 끝까지 한 번 돌리는 가장 얇은 형태다. 용어는 [GLOSSARY.md](../../../GLOSSARY.md)를 따른다(페르소나, 대화, 턴, 교정).

연결된 결정 계약:
- [llm-models](../../decisions/llm-models.md) — OpenAI 직접 호출과 대화·교정에 쓸 모델·설정, 교정 품질 미달 시 올릴 모델. 모델 선택은 이 계약을 따른다.
- [deployment](../../decisions/deployment.md) — 이번 작업은 배포하지 않지만, "LLM API 키는 서버에서만 쓰고 브라우저로 내려보내지 않는다"는 원칙은 이 계약을 따른다.
- [ui-composition](../../decisions/ui-composition.md) — 화면 구성은 shadcn 공식 component를 기본으로 한다.

## 사용자에게 보이는 결과

PC에서 개발 서버로 앱을 켜고 데스크톱 Chrome으로 열어 다음을 할 수 있다.

1. 새 대화를 누르면 미리 저장된 페르소나 중 하나가 무작위로 뜬다. 페르소나의 역할, 이름, 상황이 짧게 보인다.
2. 대화를 시작하면 페르소나가 먼저 영어로 말을 건다. 소리로 들리고 글자로도 보인다.
3. 내가 영어로 말하면 받아 적힌 내 말이 보이고, 페르소나가 소리와 글자로 답한다. 진행 표시가 현재 턴과 목표(예: 7/20)를 보여 준다. 마이크 대신 입력창에 영어 문장을 직접 쳐서 보낼 수도 있고, 말한 것과 똑같이 처리된다(테스트할 때나 소음으로 음성 인식이 안 될 때 쓴다). 대화 화면의 "소리 끄기" 스위치를 켜면 페르소나의 답이 소리 없이 글자로만 나온다.
4. 20턴에 도달하면 진행 표시가 목표 달성으로 바뀌고 페르소나가 자연스럽게 마무리를 제안한다. 대화는 계속 이어 갈 수 있다.
5. 내가 영어 종료 문구("Let's stop here", "I'm done" 등)를 말하거나 종료 버튼을 누르면 대화가 끝난다.
6. 대화가 끝나면 교정 화면이 뜬다. 내가 한 문장 중 고칠 것이 있는 문장마다 원래 문장, 고친 문장, 짧은 한국어 설명이 보인다.
7. 교정 화면에서 바로 새 대화를 시작할 수 있다.

## 승인된 범위

- 미리 저장된 페르소나 목록과 그중 무작위 하나로 새 대화 시작
- 영어 음성 대화(내 말은 음성 인식, 페르소나 말은 음성 합성과 글자)
- 음성 대신 글자로 입력해서 보내기(입력창과 보내기 버튼, Enter). 음성 인식과 같은 턴 규칙과 종료 문구를 따른다.
- 페르소나의 음성 재생을 끄는 "소리 끄기" 스위치. 켜면 답이 글자로만 나오고, 설정은 이 브라우저에 기억된다.
- 턴 세기, 20턴 목표 달성 표시, 목표 이후 대화 계속
- 영어 종료 문구와 종료 버튼으로 대화 종료
- 대화 후 단어·문장 교정 화면
- PC의 개발 서버(`localhost`)와 데스크톱 Chrome에서 동작

## 수용 기준

PC에서 개발 서버를 켜고 데스크톱 Chrome으로 확인한다.

- AC1. 새 대화를 여러 번 누르면 미리 저장된 페르소나 중 하나가 뜨며, 10번 누르면 두 종류 이상이 나온다. 뜬 페르소나의 역할, 이름, 상황이 보인다.
- AC2. 대화를 시작하면 페르소나의 첫 영어 발화가 소리로 재생되고 글자로도 보인다.
- AC3. 내가 영어로 한 문장을 말하면 받아 적힌 문장이 화면에 보이고, 이어서 페르소나의 답이 소리와 글자로 나온다. 이때 진행 표시가 1 늘어난다.
- AC4. 20번째 턴이 끝나면 진행 표시가 목표 달성 상태로 바뀐다. 21번째로 말해도 대화가 이어지고 진행 표시는 21로 늘어난다.
- AC5. 대화 중 "Let's stop here", "I'm done", "Let's finish" 중 하나를 말하면 대화가 끝나고 교정 화면으로 넘어간다. 종료 버튼을 눌러도 같다. 종료 문구가 아닌 일반 문장(예: "I'm done with my homework already, and you?")에서는 대화가 끝나지 않는다.
- AC6. 대화 중에는 페르소나가 역할을 깨고 내 문법을 고쳐 주지 않는다. 교정은 종료 뒤 교정 화면에서만 보인다.
- AC7. 교정 화면에 고칠 것이 있는 내 문장마다 원래 문장, 고친 문장, 한국어 설명이 보인다. 고칠 것이 없으면 없다고 표시된다.
- AC8. 교정 화면에서 새 대화를 시작하면 AC1의 상태로 돌아간다.
- AC9. 브라우저 개발자 도구의 네트워크 응답과 페이지 소스 어디에도 OpenAI API 키가 나타나지 않는다.
- AC12. 대화 중 입력창에 영어 문장을 쓰고 보내기 버튼(또는 Enter)을 누르면, 마이크로 말한 것과 똑같이 처리된다. 내가 쓴 문장이 내 말 자리에 보이고, 페르소나가 소리와 글자로 답하며, 진행 표시가 1 늘어나고, 입력창은 비워진다. 이때 음성 인식은 시작되지 않는다. 입력창에 종료 문구("I'm done" 등)만 써서 보내면 대화가 끝난다. 공백뿐인 입력은 보내지지 않는다. 페르소나의 답을 기다리거나 말하는 동안에는 보낼 수 없고, 같은 순간에 두 번 보내도 한 번만 처리된다. 답을 받지 못하면 입력했던 문장이 입력창에 그대로 돌아온다.
- AC13. 대화 화면의 "소리 끄기" 스위치를 켜면 페르소나의 답(첫 인사 포함)이 소리로 재생되지 않고 글자로만 나오며, 답이 오자마자 다음 입력(말하기나 글자)을 할 수 있다. 페르소나가 말하는 중에 켜면 재생이 멈추고 곧바로 입력할 수 있다. 끄면 다음 답부터 다시 소리가 난다. 설정은 새 대화로 넘어가도, 페이지를 새로고침해도 유지된다. 저장소를 쓸 수 없는 브라우저에서는 기억하지 못할 뿐 동작은 한다.
- AC14. 페르소나의 답이나 교정을 받지 못했을 때 화면 안내는 이유를 가려서 보여 준다. 서버에 OpenAI 키가 없으면 그 사실을, AI 서비스 호출이 실패하면 서버 로그에서 원인을 볼 수 있다는 점을, 로그인이 풀렸으면 다시 로그인하라는 점을 알려 준다. 서버에 닿지 못했으면 연결하지 못했다는 점을, 서버가 JSON이 아닌 응답을 보냈으면 그 사실을 알려 준다. 이유를 알 수 없는 실패는 이유를 지어내지 않고 서버 응답 코드(예: 500)만 알려 준다. 이 안내 덕분에 어떤 빌드가 돌고 있는지와 무엇이 실패했는지를 화면 문구만으로 알 수 있다. 서버는 키가 없어 요청을 막을 때 그 이유를 로그에 남기고, 키 값은 남기지 않는다.

LLM 출력 품질 기준(eval로 증명한다. 실행마다 결과가 다르므로 아래 기준을 낮추지 않는다):

- AC10. 교정 정확도: 문법·어휘 오류를 심어 둔 대화 기록 10개(오류 총 20개 이상, 오류 없는 문장 20개 이상 포함)에서 교정이 심어 둔 오류의 80% 이상을 지적하고, 원래 맞는 문장을 틀렸다고 고치는 비율이 10% 이하다. 사례는 DailyDialog의 공개 일상 대화 발화를 바탕으로 만들고, 구현 중 프롬프트를 고칠 때 보지 않는 별도 사례로 둔다.
- AC11. 역할 유지: 내가 일부러 문법 오류를 섞어 말하는 대화 기록 10개에서 페르소나가 대화 중 역할을 깨고 교정하는 응답이 전체 응답의 5% 이하다. 사례 출처와 분리 원칙은 AC10과 같다.

## 확정된 제약과 이유

- **첫 결과는 PC에서 확인한다**: 개발 서버의 `localhost`에서는 배포 없이도 브라우저가 마이크를 허용하므로, 배포와 아이폰 대응 없이 대화가 쓸 만한지를 먼저 확인한다. 사용자 확정.
- **모델**: OpenAI API를 직접 호출한다. 대화 응답은 `gpt-6-luna`(`reasoning.effort: low`), 교정은 같은 `gpt-6-luna`에 `reasoning.mode: pro`를 켠 것이며, 교정이 AC10을 통과하지 못하면 `gpt-6.1-terra`로 올린다. 버전 고정 ID만 쓰고 `store: false`로 보낸다. 이유와 비용 추정은 [llm-models](../../decisions/llm-models.md)에 있다.
- **턴 정의**: 내가 한 번 말하고 페르소나가 한 번 답하면 1턴이다. 사용자 확정.
- **20턴은 목표이지 한도가 아니다**: 도달하면 달성을 표시하고 마무리를 제안하지만 대화는 계속할 수 있다. 말문을 틔우는 게 목적이라 더 말하고 싶을 때 막지 않는다. 사용자 확정.
- **종료는 영어 문구와 버튼 둘 다**: 음성 인식은 영어로 듣고 있어서 한국어 "종료하자"를 알아듣지 못한다. 영어로 마무리하는 것도 연습이 되고, 인식이 안 될 때는 버튼으로 확실히 끝낸다. 사용자 확정.
- **교정은 대화가 끝난 뒤에만**: 대화 중 몰입을 깨지 않는다(`PRODUCT.md` 경험 원칙).

## 가정 (에이전트가 정한 기본값, 바꿀 수 있음)

- 미리 저장된 페르소나는 출퇴근 회화에 맞는 5개로 시작한다(예: 카페 주문, 호텔 체크인, 동료와 스몰토크, 병원 접수, 이직 면접). 내용은 구현에서 쓴다.
- 말하기는 마이크 버튼을 눌러 시작하고, 말이 끝나 잠시 조용해지면 자동으로 보낸다. 말할 시점을 내가 정해서 주변 소리나 페르소나의 음성이 내 말로 잘못 받아 적히지 않게 한다.
- 페르소나의 답은 소리와 함께 항상 글자로도 보여 준다.
- 대화와 교정 결과는 저장하지 않는다. 교정 화면을 떠나거나 새로고침하면 사라진다.
- 페르소나의 말투는 레벨 맞춤 기능이 생기기 전까지 쉬운 영어(대략 CEFR B1)로 고정한다. 아래 보류 항목의 임시 동작이다.
- 화면 구성은 [ui-composition](../../decisions/ui-composition.md)을 따르고, 나중에 휴대폰에서 쓸 것을 고려해 좁은 화면에서도 깨지지 않게 한다. 별도 프로토타입 검토 없이 구현에서 정한다.

## 범위 밖과 이유

- **아이폰에서 지하철 사용**(Vercel 배포, 접속 비밀번호, 아이폰 Safari 확인) — 다음 결과로 미룬다. 정해 둔 방식은 [deployment](../../decisions/deployment.md)에 있다. 참고로 MDN browser-compat-data(2026-11-19 확인)에 따르면 iOS Safari는 음성 인식을 `webkit` 접두어로 14.5부터 지원하고, 연속 인식(`continuous`)은 17부터 제대로 동작하며, 음성 합성도 지원한다. 아이폰 받아쓰기 설정이 꺼져 있으면 음성 인식이 동작하지 않을 수 있다는 점(미확인)은 그 작업에서 확인한다.
- **발음 피드백** — 다음 결과로 미룬다. 범위는 `PRODUCT.md`에 확정되어 있다(다르게 인식된 단어, 발음 기호, 원어민 발음까지).
- 페르소나 추가, 편집(상황 입력), 특정 페르소나 불러오기, "새 컨텐츠"로 AI가 새 페르소나 제안하기 — 핵심 흐름 한 바퀴에 필요하지 않다.
- 막힐 때 한국어로 묻는 힌트 — 음성 인식이 영어로 듣는 중에는 한국어를 알아듣지 못하는 같은 문제가 있으니, 그 작업에서 입력 방식을 따로 정한다.
- 대화 기록 저장과 지난 교정 다시 보기 — 이번 흐름에 필요하지 않다. 사용자가 나중에 Supabase를 연결할 계획이므로 저장은 그때 다룬다.
- 사용자 계정, 여러 사용자 — 개인용 앱이다.

## 보류 항목

- **레벨 맞춤** (`PRODUCT.md`: 페르소나의 말은 내 영어 수준에 맞춘다): 내 수준을 어떻게 정하고 반영할지 아직 정하지 않았다.
  - 임시 동작: 페르소나는 쉬운 영어(대략 CEFR B1)로 말한다. 레벨 맞춤 결정이 이를 대체한다.
  - 다시 열 조건: 이 spec이 구현되어 PC에서 대화 한 바퀴가 돌아간 뒤, 다음 작업 단위로 레벨 맞춤을 shape할 때.

## 남은 위험

- PC 마이크와 브라우저 음성 인식의 정확도가 낮으면 받아 적힌 문장이 내가 한 말과 달라지고, 교정이 내가 하지 않은 실수를 고칠 수 있다.
- 데스크톱 Chrome의 음성 인식은 Google 서버를 거치므로 인터넷 연결이 필요하다.

## Setup before implementation

- OpenAI API 키 발급과 결제 설정(ChatGPT 구독과는 별도) — 대화와 교정 호출에 필요하다. 완료 조건: 앱 밖에서 그 키로 OpenAI Responses API에 `gpt-6-luna`를 직접 호출해 정상 응답을 받는다.

## Post-release check

None.
