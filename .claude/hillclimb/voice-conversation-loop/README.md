# voice-conversation-loop 평가 (AC10 교정 정확도, AC11 역할 유지)

`docs/specs/voice-conversation-loop/spec.md`의 두 LLM 품질 기준을 재는 평가입니다. 평가는 동작하는 모델이 정해질 때마다 같은 사례와 채점 기준으로 다시 돌립니다.

## 구성

- `ac10-cases.jsonl`: 교정 사례 10개. 대화마다 학습자 발화 6개 중 3개는 오류 1개씩, 3개는 정답입니다(오류 30개, 정답 30개). `truth`에 정답 표가 있으므로 **평가받는 모델에 보여 주지 않습니다.**
- `ac11-cases.jsonl`: 역할 유지 사례 10개. 페르소나 5종을 모두 쓰고, 대화마다 학습자 발화 7개에 모두 오류를 넣었습니다.
- `prep.ts`: 시도별 입력(`trials/`)을 앱의 실제 프롬프트 빌더로 만듭니다. 사용법은 `bun run prep.ts <reps> <ac10|ac11> <all|id,...>`.
- `score10.ts`, `score11.ts`: 모델 출력을 앱의 실제 서버 코드(`handleFeedback`)로 읽고 채점 입력을 만듭니다.
- `final10.ts`, `final11.ts`: 채점자 판정을 합산해 지표를 냅니다.
- `trials/`, `errors/`, `judge-*.json`은 실행 산출물이라 git에서 제외합니다.

## 실행 순서

1. `prep.ts`로 입력을 만든다. 사례당 2회.
2. 평가받는 모델이 각 시도의 `system.txt`와 `user.txt`(교정) 또는 `learner.txt`(역할 유지)를 읽고 `output.txt`(교정, 모델의 원문 그대로) 또는 `output.json`(역할 유지, 첫 인사 + 학습자 발화마다 한 응답, 총 8개 문자열)을 쓴다.
3. `score10.ts` / `score11.ts`로 채점 입력(`judge-input-*.json`)을 만든다.
4. 평가받는 모델과 **다른** 모델이 채점한다(아래 기준). 결과를 `judge-output-*.json`에 쓴다.
5. `final10.ts` / `final11.ts`로 지표를 낸다. 채점자 대조 항목 4개가 모두 맞아야 결과를 믿는다.

## 채점 기준

- **AC10 채점자**: 항목마다 `fixed`를 판정한다. 모델의 수정문이 심어 둔 오류를 실제로 고치고, 새 오류를 만들지 않으며, 학습자의 뜻을 유지하면 참이다. 문장부호와 대소문자 차이는 무시하고, 다르지만 똑같이 맞는 수정도 참이다. 수정이 없으면 거짓이다.
- **AC10 지표**: `recall_fixed`(심어 둔 오류 중 제대로 고친 비율, 기준 80% 이상), `false_correction_rate`(정답 문장을 건드린 비율, 기준 10% 이하). 정답 문장 판정은 프로그램이 한다(정답 발화에 대응하는 수정 항목이 있으면 거짓 교정).
- **AC11 채점자**: 응답마다 `breaks_role`을 판정한다. 학습자의 문법·어휘·발음을 고치거나, 학습자의 영어를 평가하거나 칭찬하거나, 표현을 가르치거나, AI·수업·연습을 언급하면 참이다. 장면 속에서 올바른 형태를 자연스럽게 쓰기만 하면 거짓이다.
- **AC11 지표**: `role_break_rate`(기준 5% 이하).
- **채점자 점검**: 정답이 정해진 대조 항목을 매번 섞는다(AC10: 정답 수정 2, 엉뚱한 수정 2, AC11: 역할 이탈 2, 정상 응답 2).

## 결과 (2026-11-19, 평가받은 모델: Claude Haiku, 채점: Claude Sonnet)

| 기준 | 지표 | 결과 | 목표 |
|---|---|---|---|
| AC10 | 심어 둔 오류를 제대로 고친 비율 | 57/60 = 95% | 80% 이상 |
| AC10 | 정답 문장을 잘못 고친 비율 | 0/60 = 0% | 10% 이하 |
| AC11 | 역할을 깬 응답 비율 | 0/160 = 0% | 5% 이하 |

- 사례당 2회, 시도 40개. 모델이 응답 개수를 틀리게 낸 1건(`p04_rep2`)은 결과로 세지 않고 다시 돌렸다.
- 놓친 오류 3건은 모두 대화 `c07`에서 나왔다. `reserve an appointment`(어휘 선택, 2회 모두), `looking forward very much to it`(어순).
- 95%의 신뢰구간은 대략 86–98%(60건 기준)로 목표 80% 위에 있다.

## 한계

- **앱의 최종 모델이 아니라 Claude Haiku의 점수입니다.** 모델 결정(`docs/decisions/llm-models.md`)이 확정되면 그 모델로 다시 돌려야 이 기준을 통과했다고 말할 수 있습니다.
- 평가는 서브에이전트로 했습니다. 역할 유지는 모델이 학습자 대사를 한 번에 읽은 뒤 한 턴씩 답하게 했으므로, 앱처럼 한 턴씩만 받는 경우보다 유리할 수 있습니다.
- 사례는 DailyDialog를 내려받지 않고 같은 스타일(일상 대화)로 프롬프트를 모르는 별도 에이전트가 썼습니다. 스펙이 정한 "DailyDialog 발화를 바탕으로"와 다릅니다.
- 처음부터 점수가 목표를 크게 넘어 개선할 여지가 없었으므로(baseline이 이미 green), 사례가 쉬운 편입니다. 모델을 바꾸거나 프롬프트를 고칠 때를 대비해 더 어려운 사례(애매한 오류, 여러 오류가 섞인 발화, 장면 밖 질문)를 보강하는 것이 좋습니다.
- 회귀 묶음(regression suite)으로 졸업시키지 않았습니다. 평가받는 모델이 서브에이전트라 사람이 없는 환경에서 다시 돌릴 수 없기 때문입니다. 실제 모델을 부를 수 있게 되면 그 호출로 실행기를 바꾸고 졸업시킵니다.
